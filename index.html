What this file is

A self-contained page, not a connected app

This is a single HTML file with the docket data written into it. It doesn't need installing, doesn't need an internet connection, and doesn't talk to Clio or anyone else's computer. Opening it means double-clicking the file.

This copy

Reset for September — genuinely clean, not just visually empty

This version starts from September, with no earlier months carried over, and fixes a labelling bug from the previous version where every matter — including ones added by hand — was incorrectly tagged "imported." Only matters actually brought in via CSV now show that tag; matters restored from an old-format backup show "migrated" instead, so it's clear where each one came from. Nothing appears until you add a matter, import a CSV, or restore a backup.

Treat this as a distinct file rather than overwriting an older copy of the dashboard at the same filename — a couple of browsers reuse local storage across files with the same name and location, which is the most likely explanation for numbering looking odd previously. Saving this under a new filename avoids that entirely.

Client names

The "Client name" field is optional and entirely up to you

There's no default data of any kind in this file, so there's nothing to worry about out of the box. If you fill names in locally, they're saved the same way every other edit is: to this browser, tied to this exact file, never sent anywhere. That also means the moment you'd consider sharing, backing up to a wider location, or hosting this file anywhere more visible than Dillex's own secure storage, treat it as containing real client data and handle it accordingly.

Storing and backing it up

Treat it exactly like a Word or Excel file

  • Save it wherever Dillex's normal backup already covers — network drive, firm OneDrive/SharePoint, or the same location other case documents live.
  • To share with a colleague, send the single .html file — nothing else is needed.
  • To refresh it with up-to-date figures later, ask again with the latest export — it can be regenerated, not synced.
Editing, importing and exporting

Edits, imports and notes all save to this PC and this file location only

Every dropdown, category pill, text field and note box saves to the browser's local storage automatically as you go — there is no separate "save" step anywhere in this tool, and typing pauses for under a second before it's written. That storage is tied to this exact file in this exact folder on this exact computer; edits won't appear if the file is copied elsewhere or opened by a colleague from their own copy, since each copy keeps its own separate edits. Use Backup edits to save your changes as a separate JSON file, and Restore edits to reapply them to a fresh copy of this dashboard later.

🔗 Auto-save to a file (Chrome or Edge only) goes a step further: pick or create a file once, and every change from then on writes to that same file automatically, a couple of seconds after you make it — no repeated downloads, no separate backup step, and the on-screen backup reminder switches itself off while it's connected. This only lasts for the current browser session — reopening the file later means reconnecting with one click, since browsers require that click before letting a page write to your disk again. Firefox and Safari don't support this at all; on those, the regular Backup/Restore buttons and reminder are what to rely on.

+ Add matter on the All matters page opens a single-entry form — month comes first since that's the one thing every matter needs, client name and everything else is optional or defaults sensibly.

Import from CSV reads a spreadsheet straight from your computer — nothing is uploaded anywhere. Use CSV template first for the expected columns. Imported matters carry a green "imported" tag and can be removed with the ✕ button.

+ Add new month extends the docket forward from September, one month at a time. When you add one, any matter still sitting in the previous month that isn't finished/concluded or closed automatically moves forward into the new month, so nothing open quietly falls out of view. It suggests the next calendar month automatically, but you can type any label you want.

Each of the four matter pages can export its currently filtered rows to PDF via the browser's own print dialog (choose "Save as PDF") — this works offline, without any external service.

Tracking hearings and directives

Next hearing and next directive, sorted automatically; full history kept alongside

On Ongoing matters, each matter has a Next hearing date field and shows its Next directive due date, and the page sorts by whichever of the two is nearer — anything without either sits at the bottom. Rows are highlighted amber if a hearing is due today or has passed, and red if a directive is overdue. Untick "Sort by nearest date" if you'd rather see the plain list.

Click + note on any matter, on any page, to open its hearing / progress log and court directives alongside the notes box. The hearing log is a running history of what's happened (date, event, outcome), newest first. Directives are due-dated tasks — file a statement, disclose documents, and so on — each with an Outstanding/Complied toggle; overdue ones are shown in red. Both stay attached to the matter even after it moves to Finished/concluded or Closed, so the full history and compliance record are still there later. The overview at the top of the page includes a running count of overdue directives across the whole caseload.

HMCTS online portal

A simple flag, plus an optional reference number

Each matter on Ongoing matters has an HMCTS portal column (Yes / No / Unknown) — a quick way to see which live matters are being managed through the portal versus paper-based. If you need to record the actual portal reference number, that lives inside the same expandable area as the notes and hearing log (click + note).

Who has conduct

A free-text field, filterable and groupable, plus a "my matters" view

Every matter on All matters and Ongoing matters has a Conduct field — type in whoever's running it. It's free text rather than a fixed list, so there's nothing to maintain as the team changes; type a name once and it's suggested automatically next time. Filter by fee earner, or group All matters by fee earner to see everyone's caseload side by side. The overview also has a collapsible workload breakdown showing matter counts per person, including anything unassigned.

Enter your own name in the small box next to the filters, then tick My matters only to see just your own caseload — the name is remembered for next time, in this browser.

Flagging for review

A quick marker, separate from status

The 🚩 button on each matter (next to "+ note") marks it for review — useful for supervision, or anything that needs a second pair of eyes regardless of what stage it's at. Flagged matters get a coloured edge in the table and count toward a Flagged for review figure in the overview; tick Flagged only on All matters to see just those.

Finding things faster

A search that works from anywhere, and headers that stay in view

The search box at the top of the page works regardless of which tab you're on — type a case number or client name and press Find (or Enter) to jump straight to it in All matters, with every other filter cleared out of the way. Table and tab headers now stay visible as you scroll down a long list, so you're never guessing which column — or which section — you're looking at partway down the page. Each tab also shows a live count, so you can see at a glance how much is in Ongoing, Finished/concluded or Closed without opening them.

Keyboard shortcuts: press / from anywhere to jump into the search box, 1–6 to switch between Needs attention, All matters, Ongoing, Finished/concluded, Closed and this page, and Escape to close an open note panel or dialog.

On All matters, a Sort by control sits next to Group by — case number, date added, next hearing date, next directive due, or client name, applied within whatever grouping you've chosen. Whatever you set — filters, sort, grouping — is remembered next time you open this file, so you're not rebuilding the same view every session.

If you've made changes since your last backup, a reminder appears near the top with a one-click Backup now button — dismissible for the current session if you're mid-task and not ready yet.

Needs attention

The landing page — what to look at today, in one place

This is now the first tab you see. It pulls together hearings due in the next 7 days, overdue directives, anything flagged for review, and active matters with nobody assigned — each with a one-click Open → straight to the matter. Nothing here is separately stored; it's all computed live from the same data as the other pages, so there's nothing extra to keep in sync.

It also flags possible duplicates — two matters sharing the same case number (almost always a data entry slip, worth fixing) and two matters sharing the same client name (which can be entirely legitimate, a returning client with a new matter, but worth a quick glance to be sure it isn't an accidental double entry).

Given the subject matter

Handle the file the way you'd handle any case list

  • Keep it inside Dillex's normal secure storage rather than personal cloud accounts or personal email.
  • Delete or archive old snapshots properly rather than letting stray copies build up.
  • If several people at the firm need to view and jointly edit the same live list, a static file like this isn't the right long-term tool — that needs an actual shared, permissioned system.
