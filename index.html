Status hygiene

Three status pages now exist — worth agreeing what each means

This version splits closure into three states: not proceeding (client didn't go ahead — pre-issue), finished/concluded (matter ran its course, outcome reached), and closed (file administratively wrapped up). That's a reasonable three-way split for a family law caseload, but it only works if everyone uses the categories the same way — worth a one-line house rule so "not proceeding" isn't used interchangeably with "closed".

  • Legal aid matters marked not proceeding need a funding closure step before they can move to closed — that's why the not proceeding page flags them separately.
  • Charlie May Perry is flagged "no response" — worth a decision point (chase again vs mark not proceeding) rather than sitting indefinitely.

What this file is

A self-contained page, not a connected app

This is a single HTML file with the docket data written into it. It doesn't need installing, doesn't need an internet connection, and doesn't talk to Clio or anyone else's computer. Opening it means double-clicking the file. It's a snapshot: it shows the docket as it stood on 29 Jul 2026 and won't update itself as Clio changes.

Storing and backing it up

Treat it exactly like a Word or Excel file

  • Save it wherever Dillex's normal backup already covers — network drive, firm OneDrive/SharePoint, or the same location other case documents live.
  • To share with a colleague, send the single .html file — nothing else is needed.
  • To refresh it with up-to-date figures later, ask again with the latest export — it can be regenerated, not synced.
Editing categories, status, legal aid and notes

All edits save to this PC and this file location only

Every dropdown and note box on this page saves to the browser's local storage, tied to this exact file in this exact folder on this exact computer. Practically:

  • Your edits will still be there next time you open this exact file from this exact location on this PC.
  • They will not appear if the file is copied elsewhere, moved, or opened by a colleague from their own copy — each copy keeps its own separate edits.
  • Clearing browser site data, or switching browsers, will also clear them.

Treat this as a fast working view for one person to triage and annotate the docket — Clio remains the system of record. If several people need to edit the same live list together, that needs an actual shared, permissioned system rather than a static file; happy to talk through options if useful.

Given the subject matter

Handle the file the way you'd handle any client-identifiable case list

  • Keep it inside Dillex's normal secure storage rather than personal cloud accounts, personal email, or an uncovered personal device.
  • Delete or archive old snapshots properly rather than letting stray copies with client names sit in downloads folders.
New: backup and restore

"Backup edits" saves your changes as a small file you can keep separately

The Backup edits (.json) button at the top downloads everything you've changed — categories, statuses, legal aid positions, notes — as a small JSON file, separate from the dashboard itself. Restore edits from backup reads that file back in. This exists for two situations:

  • You're given a freshly regenerated copy of this dashboard (say, after August's intake is added) and want to reapply the edits you'd already made, rather than redoing them from scratch. This only lines up correctly if the case numbers haven't changed between versions.
  • You want a second copy of your edits somewhere safer than one browser's local storage, before clearing your browser data or moving to a new PC.

The backup file only contains your edits, not the underlying docket — it's meaningless without a copy of this dashboard to restore them into.

New: export to PDF

Every page can be printed to PDF, filtered by month

Each page has an Export shown rows as PDF button. It respects whatever filters are currently set — so selecting "July" on the Not proceeding page and exporting gives you a PDF of just July's not-proceeding matters. Clicking it opens your browser's normal print dialog; choose "Save as PDF" (or "Microsoft Print to PDF" on Windows) as the destination instead of a physical printer. This uses the browser's built-in printing, not an external service, so it works offline.

Hosting this as a webpage — worth real caution here

GitHub Pages can technically host it, but not with real client data on it

Because this is a single static HTML file, GitHub Pages genuinely can serve it as a URL-accessible page — that part's straightforward. The problem is what GitHub Pages sites are visible to: on a standard GitHub account, a Pages site is publicly reachable by anyone with the URL, regardless of whether the underlying repository is marked private — GitHub only restricts Pages access behind sign-in for Enterprise Cloud organisations with that feature enabled, not for ordinary free or personal-plan repos.

That means publishing this file as-is would put real, named domestic abuse, care proceedings and financial matter clients on the open internet — a serious confidentiality problem and very likely a data protection breach, independent of anything to do with GitHub specifically.

  • If a browser-accessible version genuinely helps, the safer route is hosting it somewhere access-controlled that Dillex already uses — the firm intranet, a password-protected SharePoint site, or an internal server — not a public static host.
  • GitHub Pages is a reasonable place to host a template version of this tool with placeholder names and no real client data, if the goal is to demonstrate or reuse the structure — happy to prepare that version separately if useful.
  • Genuinely private, multi-user hosting (so several people at the firm can view and edit the same live list) is a different kind of project — a small web app with real access control and a database — rather than a static file on any free host.
New: editable names and bulk import

Client names can be edited in place, and new intake can be imported from a CSV

Every name field — on the Pipeline, Ongoing and all three status pages — is now a text box; click into it and type to rename. This is what makes the template version actually usable: replace "Client 001" with a real name locally, on your own machine, and it stays there (subject to the same per-file, per-PC storage rules as everything else).

Import intake from CSV reads a spreadsheet file directly from your computer — nothing is uploaded anywhere, the browser just opens and reads the file locally, the same way it reads any file you attach to an email. Use Download CSV template first to get the expected column headings (Name, Month, Source, Category, Status, Legal aid — only Name is required, everything else defaults sensibly if left blank or misspelled). Imported matters appear on the Pipeline page with a green "imported" tag and their own ✕ button if you need to remove one; they behave exactly like the built-in matters otherwise — filterable, editable, exportable to PDF.
